# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Defog: a browser-only tool that reads a Fog of World `Sync/` folder (or backup .zip) and overlays visited ground on a Leaflet map, then plans/suggests routes that defog the most new area. The fog data never leaves the browser; only bounding boxes go to Overpass and tile numbers to the elevation tile host (see README "Privacy" before adding any network call).

## Running and deploying

- No build, package manager or linter; tests are plain Node scripts in `bench/*.test.js` (offline, synthetic data). `app/` is the site root: serve it with any static file server and open `index.html`.
- No GitHub Pages site: `app/` ships only inside the phone app in `mobile/` (bundled into `generated/web.ts` by `pnpm generate`).
- `Sync/` (personal location history) is gitignored: never commit it or anything derived from it.
- Third-party libs are vendored in `app/vendor/`; there is nothing to install.

## Architecture

Every file in `app/src/` is a plain IIFE that hangs its API on `window` (e.g. `FogParser`, `StreetIndex`, `SuggestTool`). There are no imports: **load order in `app/index.html` is the dependency graph**, so a new file must be added there after what it uses and before `main.js`.

Data flow:
- `unzip.js` / `parser.js`: Sync tiles (zlib) -> `FogMap` of visited cells. Fog grid is 2^22 cells wide, 1 cell = 1 px at map zoom 14; `parser.js` also owns the cell <-> lng/lat math everything else uses.
- `parser.js` also keeps what a writer needs: `Tile.blockExtra(idx)` / `Tile.blocks()` hand out each block's bitmap and its 3 extra bytes (10 region bits + checksum `2*popcount+1`), and `FogMap` has an overlay of cells the app added (`addCells(Int32Array of [cx, cy] pairs) -> number new`, `clearOverlay()`), `version` (bumped by `addTile`, `addCells`, `clearOverlay`), `totalVisited()`, and `blocks()` (every non-empty block, overlay ORed into the imported block). `isVisitedCell`, `countVisitedInCellRect` and `latLngBounds` include the overlay; `tileCount` still counts imported tiles only.
- `md5.js` / `fogWriter.js`: `MD5.hex` and `FogWriter` (`tileName(id)`, `writeTile(blocks)`, `writeSync(fogMap, {deflate}) -> [{name, bytes}]`), Fog of World's Sync format. Imported blocks keep their region bits, new blocks get region 0, empty blocks and tiles are never written. `bench/fixtures/fow/` holds two tiles Fog of World wrote (from Fog Machine, MIT) that must round-trip byte for byte. The default `deflate` is `pakoDeflate.deflate` at level 5: `vendor/pako_deflate.min.js` and `pako_inflate.min.js` both assign `window.pako`, so the deflate build loads first and `src/pakoDeflate.js` parks it as `window.pakoDeflate`. Node's own `zlib` is Chromium's fork and does not reproduce Fog of World's level-5 bytes; pako does. Load order: `md5.js`, `fogWriter.js` after `parser.js`.
- `reveal.js`: `Reveal.reveal(track, rules) -> Int32Array` of `[cx, cy]` pairs (sorted by `cx` then `cy`, unique), the cells a recorded track explores; `Reveal.RULES` is the versioned rule set (`version`, `maxAccuracyM`, `maxGapS`, `maxGapM`, `halfWidthM`; placeholder numbers). Pure: points with a worse accuracy are dropped, consecutive points join into a segment only within the time and distance gaps (an antimeridian crossing is a gap, and a gap leaves each end as its own disc, so nothing between the ends is revealed unless they are closer than `2 * halfWidthM`), and a cell is revealed when its centre lies within `halfWidthM` of a segment or an isolated point. Latitudes clamp to ±85.0511; a disc at the antimeridian wraps to the other side of the grid. Load order: after `parser.js`.
- `fogLayer.js`: Leaflet GridLayer painting the fog (paints one side, composites with a CSS blend mode on the pane).
- `overpass.js`: `Overpass.post`, the only Overpass caller: endpoints in a user-set order (overpass-api.de, then private.coffee), one request in flight. An endpoint is abandoned when no response headers arrive within 15 s or the whole answer is not in within 30 s (a stall: held 30 s, or 10 min from the third stall in a row with no finished answer in between), held at least 30 s (longer when Retry-After says so) after a 429 or a rejected fetch (network error, CORS-hidden answer), and held 1 h after a 406 (the day's share used up; longer when Retry-After says so); any other non-2xx answer, or a 200 whose body is not JSON, moves on to the next endpoint with no hold. A failed post carries `err.reason` (`blocked`, `busy`, `stalled`, `offline`, `server`, in that precedence, never server text) and `err.retryAt` only when every endpoint is held (the first hold's end, the first block's when the reason is `blocked`); the error thrown is the one that earned the reason (a held endpoint keeps the error of its hold), so a 406 on one endpoint, then or within its hour, is not reported as the next one's silence. `StreetIndex.rectQuery` asks `[timeout:25]` so the server ends a query by 25 s, before the 30 s whole-answer limit, even one the client gave up on at 15 s. Load order: before `streets.js`.
- `streetMessages.js`: `StreetMessages.describe(err, now)` and `progress(done, total)`, pure (no DOM, no Leaflet), what the suggestion card, the route hint and the "Streets in fog" badge say about a street download. `describe` reads only `err.reason` (`busy`, `blocked`, `stalled`, `offline`, `streets-partial`; `server`, anything else or nothing gets the generic text), `done`, `total`, `retryAt` (rounded up to 10 s, in minutes past two) and, for `streets-partial`, `err.cause.reason`; it never prints `err.message` or anything from the server, which can hold a remark or a tile number. `bench/street-messages.test.js` also checks that `main.js` words `streets-fetch` only through it. Load order: before `streetsLayer.js` and `main.js`; not in `bench/lib/load.js` (suggest code emits counts and reasons, `main.js` words them).
- `streets.js`: `StreetIndex` fetches OSM ways on a fixed 0.025° tile grid (`tilesCovering`, `tileBounds`) through an injected street source (`opts.fetchStreets(tiles, kind, onTile, {cacheOnly}) -> Map "x:y" -> answer`, calling `onTile(tile, answer)` as each tile arrives; default `StreetIndex.overpassFetch`: one Overpass request per tile (`TILES_PER_REQUEST`), stopping at the first failure, and an empty Map when `cacheOnly`). `ensureRects(rects, kind, {onProgress, deadlineMs, cacheOnly})` asks for the missing tiles nearest the rects' centre first, merges each tile as it arrives (`version` bumps per tile), reports `{done, total}`, and stops asking once `RUN_DEADLINE_MS` has passed on the `opts.now` clock (default `Date.now`); a failed run keeps what arrived and rejects with `StreetIndex.downloadError(done, total, cause)`: `done`, `total`, `cause`, `reason` (`streets-partial` when any tile arrived, else the cause's; a server remark in a 200 and a tile the source left out are `server`) and the cause's `retryAt`; `StreetIndex.downloadFacts(err)` is the part a caller passes on (`{reason, done, total, retryAt, cause: {reason}}`, never the message). A throw from `onTile` passes through the sources unchanged; `ensureRects` wraps its own deadline throw as a download error and rejects a bug thrown while reading a tile as itself; `StreetIndex.isDownloadError(e)` (numeric `done` and `total`) tells the two apart, and every caller words only a download error as one. A whole run resolves `{done, total, missing: []}`. `{cacheOnly: true}` makes no request: it merges what the source holds, never rejects on a missing tile and resolves `{done, total, missing}` (the tiles still missing, nearest first); an expired copy (the source's Map alone) is drawn from and kept in `staleTiles` so the next cache-only read skips it, but stays out of `tiles`, so a normal run asks for it again (`_addWay` keeps the ways it already holds, so their geometry and classes are not refreshed). It scores ~50 m segments by the share of their ~30 m corridor still fogged; `invalidateFrac()` drops every cached share and bumps `version` when the fog moved. Shared by `streetsLayer.js`, `planner.js` and `suggest.js`.
- `streetsLayer.js`: `StreetsInFogLayer`, the "Streets in fog" look. A pan only reads (`ensureRects` with `cacheOnly`) and paints what is on the device, up to `MAX_TILES` (48) tiles in view (beyond: zoom in; a dense city tile is up to ~29000 of the index's lifetime 400000 segments). When pieces are missing the badge says "Street map known for k of N pieces here." with one "Download this area" button (`FETCH_MAX_TILES`, 16 missing pieces at most; beyond: zoom in, no button). The button is the only fetch: the normal `ensureRects` for the missing pieces, worded by `StreetMessages.progress` / `describe`; a second tap while it runs does nothing, a failure shows `describe`'s text without the retry time (nothing would count it down) and a "Try again" button until the map moves, a download that ends after a move does not word the new view, and nothing retries quietly. `refresh()` recounts once `main.js` swaps in the street cache. Tested by `bench/streets-layer-cache.test.js`.
- `tileStore.js` / `streetCache.js`: the street cache. `TileStore` is a key-value store with LRU eviction over the page's IndexedDB (memory fallback when IndexedDB is missing or fails; `open` never rejects). `StreetCache.create({store, network, now})` wraps a street source: per-tile answers kept 90 days, a `run` tile also stands in for `bike` (the same approximation as `StreetIndex._uncovered`: it can miss foot=no ways), keys `"2:" + kind + ":" + x + ":" + y` (the unversioned 0.05° keys are never read), each network tile stored as it arrives so a failed run keeps them, `{cacheOnly: true}` returns what the store holds (fresh through `onTile`, expired in the Map alone) and never calls the network, a store error falls back to the network, an expired copy serves only when the network fails, every tile still missing has one and the caller did not stop the run from `onTile`, and it comes back in the returned Map, never through `onTile`, so the run deadline cannot cut it off. A failure rethrows the network's error unwrapped (it needs nothing from `streets.js`); `ensureRects` counts the tiles. `main.js` opens the store with `maxEntries: 1024`, builds the `StreetIndex` on `overpassFetch`, then swaps in the cache's `fetchStreets` once the store opens. Load order: `tileStore.js` after pako, `streetCache.js` after `overpass.js`, both before `streets.js`.
- `elevation.js`: `Elevation.create({store, fetchTile, decodeTile})` / `Elevation.open()` (IndexedDB `crossfog-elevation`, 200 tiles), `elevationAt([[lon, lat]]) -> Promise<(metres|null)[]>`. AWS terrain tiles (terrarium PNG, zoom 12) from the bucket's own host, bilinear between pixel centres, edge pixel clamped at a tile border; a tile that cannot be fetched or decoded gives `null`, never a throw. Only tile numbers leave the page. Load order: after `streetCache.js`. `routeLocal.js` and the adoption of a suggestion in `main.js` call it.
- `estimates.js`: `Estimates.estimate(coords, travelMode, elevation) -> {coords (with z), distanceM, seconds, ascentM, descentM, elevationKnown}`, a port of BRouter's cheap-ruler distance, filtered ascent (10 m buffer; `{ascentFilterM: 5}` is the other value BRouter uses) and time model (Tobler walking, bike power equation, constant car speed), credited in `mobile/licenses/brouter-LICENSE.txt`. A `null` elevation is carried forward (leading ones take the first known value) and `elevationKnown` counts the real heights, so a caller can tell flat ground from heights that never arrived; a non-finite coordinate throws; a travel mode with no model gets `seconds: null`. Load order: after `elevation.js`. Called by `routeLocal.js` and by `main.js` when a suggestion is adopted; `suggest.js` takes the filtered ascent and descent of `statsFromCoords` from it.
- `route.js`: manual route tool (snapping through the injected `opts.routeWaypoints(pins, travelMode) -> {coords, stats} | {error, why}`, drag/insert waypoints, GPX; `setFixedRoute(latlngs, coords, stats)` takes a suggestion's geometry and stats without a request and returns a token for `refineFixedRoute` (heights that arrive late; ignored after an edit or `clear`)). It makes no network call and `app/` names no routing service. `routeWaypoints` gets a third argument, `onProgress({done, total})`, and the loading state carries `done` and `total` while the street download runs (a superseded request's progress is dropped). `routeRecord()` returns the `RouteRecord` the phone app's `sendRoute` carries (id and `createdAt` minted on the first call and kept through edits, new after `clear`, `setFixedRoute` or `setWaypoints`; `null` while routing is in flight or after a failure, so a straight-line fallback is never sent; the GPX names the id in `<keywords>`). `export.js`: fog -> KML.
- `routeLocal.js`: `RouteLocal.create({streets, plannerFor, elevation, estimates, streetKind}) -> routeWaypoints`: one `ensureRects` for every leg padded by 1000 m, `LocalRouter` on `SuggestTool.plannerFor(mode)` (the graphs suggestions use), `elevationAt` + `estimate`; no heights at all gives a 2D line and `null` climb. Failures are `{error, why}` with `why.reason` as `LocalRouter.explain` words it, `no-street-data` (no planner), `streets-fetch` with `why.download` (`StreetIndex.downloadFacts`) when the download failed, or `internal` when `ensureRects` threw anything else (a bug; its class is logged); `onProgress` goes to `ensureRects`. Load order: after `router.js`, before `suggest.js`.
- `planner.js`: graph search over StreetIndex ways (pockets of rewarding streets joined by reward-hungry paths, rewards spent as edges are used so loops come back on different streets). Runs locally and returns real street geometry (`coords`). Builds the street graph (components, one-way directions, travel-class filter) that `router.js` routes on. The graph's build stamp includes `fogVersion()` (fifth constructor argument; `SuggestTool` passes `() => this.fogMap.version || 0`) and the fraction cache is dropped when it moves, so a planner rebuilds its rewards in place after any fog change and nothing resets the suggestion planners by hand.
- `router.js`: `LocalRouter`, A* shortest paths over the planner graph (pins snap onto the street itself, via points, per-edge avoid penalties, `explain` for why a route failed). Load order: after `planner.js`, before `suggest.js`.
- `suggest.js`: `SuggestTool` (A->B and loop modes). Fetches streets from Overpass, then routes via-point and planner candidates locally and scores each with the `computeGain` callback it is given. A failed run emits `{error, reason, why}`; a failed street download is `{error, reason: "streets-fetch", download}` (`StreetIndex.downloadFacts`), any other throw from `ensureRects` is `{error, reason: "internal"}`, and while one runs it emits `{loading, phase: "streets", done, total}`.
- `history.js`: `HistoryPanel`, the History tab and the Send to watch button. `install({doc, map, getUnits, getRecord, phone})` finds `#historyPane`, `#sendWatch` and `#sendStatus` and returns `{panel, send}`; `phone()` is `window.crossfog || null`, looked up at each use because the adapter installs that object after this file runs. `panel.setActivities(items)` / `setTrack(id, points, route?)` are what the adapter feeds (`CrossfogPage.history`); cards and detail are built with `textContent` since the travel mode comes from the watch; "Show on map" draws into the `routes` pane (created in `main.js`); delete is a two-tap confirm in the detail, never a dialog. `send.routeStatus` / `linkStatus` are `CrossfogPage.routeStatus` / `.linkStatus`: the chip speaks for the route as it was sent (an edit or `clear` blanks it, a status for another id is ignored), "Waiting for watch" outranks "Not paired". Pure formatting helpers (`formatDuration`, `formatDistance`, `formatPace`, `statLines`) are tested by `bench/history-panel.test.js`. Load order: after `suggest.js`, before `main.js`.
- `backup.js`: `BackupButtons.install({doc, win})`, the Back up… and Restore… buttons (`#backupRow` in `#fogPane`, below the import row). They call `window.crossfog.backup()` / `restore()`; the row shows only once the page has loaded with `window.crossfog` present (the adapter installs it after this file runs), so a plain browser never shows it. The passphrase is asked by a native dialog, never in the page. Load order: after `history.js`, before `main.js`.
- `fowExport.js`: `FowExport.run({fogMap, phone, newId}) -> number of files | 0 | null`, the page half of the Fog of World export: `FogWriter.writeSync(fogMap)`, then `window.crossfog.exportBinary` chunks of at most 1 MiB raw, every chunk of one export carrying the same `exportId` and the file count `files` (the phone app cannot otherwise tell when the export is whole). `null` when there is no phone or the writer threw (the error class is logged, nothing else). Load order: after `fogWriter.js`.
- `exportWarning.js`: `ExportWarning.install({doc}) -> {ask(kind, anchor), guard(kind, action, anchor)}`, the `#exportWarning` card (kinds `fog`, `gpx`, `kml`, `maps`), moved under `anchor` because the Fog of World export sits in the Show your fog tab and the others in Plan. `guard` returns the click handler: it shows the card and runs `action` only after Continue; Cancel, Escape, a second request and an unknown kind run nothing. Every plaintext export in `main.js` goes through it, which `bench/export-warnings.test.js` checks by reading the source. Load order: after `backup.js`, before `main.js`.
- `main.js`: wires the UI, style controls, persistence, and defines `computeGain`/`cellIsNew` as closures over UI state. It ends by setting `window.CrossfogPage = {fogMap, fogChanged, reveal, history, routeStatus, linkStatus}`: the phone app's adapter (`mobile/web-adapter/history.ts`) adds and removes the cells each kept activity revealed (`fogMap.addCells` / `clearOverlay`), caches them per activity in IndexedDB, then calls `fogChanged()`, and hands the `activities` list and each assembled `track` (with the followed route's coords from the first chunk) to `CrossfogPage.history` (redraws the fog, drops street fractions, restyles "Streets in fog", updates the defog percentage and the Suggest button). The `tileCount` checks (defog percentage, Suggest button, `computeGain`) stay, and the fog layer is created only by `finishLoad()` (`ensureLayer`), so cells from activities alone are not painted until an import is loaded.

## Benchmark harness (`bench/`)

Headless Node run of the shipping suggestion code against a real `Sync/` folder in the repo root:

    node bench/characterize.js          # density maps, pick scenario centres
    node bench/run.js [out] [filter]    # run SuggestTool on bench/scenarios.js
    node bench/overpass.js [filter]     # street-network context
    node bench/route-timing.js          # routeWaypoints pin-drag timing on a cached area, offline
    node bench/compare.js <baseline.json> <candidate.json>   # acceptance check, see bench/README.md
    for t in bench/*.test.js; do node $t; done               # synthetic-graph tests, no network

- `bench/lib/load.js` `require`s `parser.js`, `md5.js`, `fogWriter.js`, `reveal.js`, `overpass.js`, `tileStore.js`, `streetCache.js`, `elevation.js`, `estimates.js`, `streets.js`, `planner.js`, `router.js`, `routeLocal.js`, `suggest.js` over `bench/lib/leaflet-stub.js`; a new app file that suggest code depends on must be added there too. It sets the Overpass order to overpass-api.de first, because `bench/cache/` holds answers from that instance.
- `bench/lib/headless.js` installs `bench/lib/tileFetch.js` on each run's `StreetIndex`: the Overpass request is the single rect of the run's `ensureRects` call (the `StreetIndex.rectQuery` text, with its `[timeout:25]` read as `[timeout:60]`, is what `bench/cache/` is keyed on), split per tile and handed to `onTile` in the order asked. `bench/run.js` prints the live request count and exits 1 when it is not 0: unless the cache was cleared, the query text changed, so fix `rectQuery`, do not refetch.
- `bench/lib/gain.js` is a hand copy of `computeGain`/`cellIsNew` from `main.js`. Change one, change the other.
- Overpass responses are cached in `bench/cache/` (gitignored); delete it to re-measure live. Overpass answers 502 under load and the run then ends in the error state: rerun after a minute, only failed requests refetch. `bench/cache/brouter/` is leftover from before suggestions went local; only `bench/estimates-cache.test.js` reads it (it skips when absent, `CROSSFOG_BROUTER_CACHE` points it elsewhere) and nothing writes it. The committed estimate fixtures are in `bench/fixtures/brouter/`. The acceptance baseline is the saved `bench/out/baseline-brouter.json`.
- Results go to `bench/out/<name>.json` (gitignored).
