# Cross the Fog (Expo app)

Read `AGENTS.md` first: Expo APIs change every SDK, so fetch the versioned docs (`expo` is `~58`, `https://docs.expo.dev/versions/v58.0.0/`) before touching an Expo, EAS or React Native API.

Android only. iOS is paused until the Android phone app and the Wear OS app are done, tested and released: no iOS builds, simulator runs, fixes or plan items before then, and every check runs on Android. `AGENTS.md`'s iOS examples do not apply.

## Commands

- Unit tests: `pnpm test` (vitest, projects `unit` and `adapter`). One file: `npx vitest run test/unit/incoming.test.ts --reporter=dot`.
- Typecheck: `pnpm typecheck` (it runs `pnpm generate` first). Lint: `npx biome check <paths>`; existing warnings in `test/adapter/hooks.test.ts` are unrelated.
- Full gate: `pnpm verify`.
- Builds: use `pnpm android`; it regenerates the web bundle first. A raw `npx expo run:*` does not.
- Android builds need JDK 21 (`JAVA_HOME=/Library/Java/JavaVirtualMachines/temurin-21.jdk/Contents/Home`), `ANDROID_HOME=$HOME/Library/Android/sdk`, and `--device <AVD name>`, not the adb serial.
- e2e builds need `CROSSFOG_E2E=1` for the web build, the app config and the prebuild, and a Release configuration. Run Maestro against them with `maestro --device <serial> test .maestro`.
- Pull requests: `gh pr create --repo leonardoazeredo/defog --base main`.
- `modules/watch-link` (Kotlin local module, hand-written and committed, unlike the generated `mobile/android/`; Gradle runs in `mobile/android` and finds it as project `:watch-link`). With the Android env above, in `mobile/android`:
  - JVM tests (`KeyWrapTest`, `KekReadTest`, `DatabaseKeyHexTest`, no device): `./gradlew :watch-link:testDebugUnitTest`.
  - Instrumented tests (`KeysTest`, real AndroidKeyStore; the AVD `chase-cashew-test` must be running): `./gradlew :watch-link:connectedDebugAndroidTest`. They run in the module's own test APK (its own UID, Keystore and `noBackupFilesDir`), so they never touch the installed app's keys.
  - `StagingStoreTest` and `FramesTest` (software key, no device) run under the same `:watch-link:testDebugUnitTest`; `StagingStoreKeystoreTest` (the real Keystore key) under `connectedDebugAndroidTest`. Set `ANDROID_SERIAL=emulator-5554` when a phone or watch is also attached.
  - Neither runs in `pnpm verify`.
- Kotlin keys: `Keys.databaseKey()` reads `noBackupFilesDir/keys/db.key.v1`; a file without the Keystore alias (or the alias without the file) is `KeyLostException`, and so is an `UnrecoverableKeyException` on the alias that repeats after one retry 200 ms later; JS sees either as `KeyLostError` from `src/platform/watchLinkModule.ts`, the only file meant to import the native module `modules/watch-link` (nothing enforces it), apart from `src/dev/devActions.ts`, which imports it directly so a static wrapper does not put `stageForTest` in the release JS. `keyState()` "existing" means the file and the alias are both present, not that they unwrap: branch on the `getDatabaseKeyHex` rejection, and treat "fresh" as safe only when no database file exists.

- Staging: activities the watch hands over wait in `noBackupFilesDir/staging/<activityId>.bin` and queued routes in `noBackupFilesDir/outbox/<routeId>.bin` (AES-GCM under the Keystore key `crossfog.staging.v1`, id as AAD; both are `StagingStore`s). The TS side is `src/link/` over `src/platform/watchLinkModule.ts`; `createFakeWatchLink()` stands in for tests. `stageForTest(offerJson)` is registered only by the `src/debug` source set (the `src/release` twin is empty), so it is absent from a release dex; check with `unzip -p <apk> 'classes*.dex' | grep -a -c stageForTest`. A staged item that no longer authenticates or parses is skipped by `pendingActivities` and stays on disk.

- Backup and restore (`src/backup/`, `src/flows/backup.ts`, `src/platform/backupPlatform.ts`): a backup is a SQLCipher file made by `SqlDriver.exportTo` (`ATTACH ? AS backup KEY ?` with both bound, never spliced, then `sqlcipher_export`; key `null` is the plaintext copy after the P5 warning), reopened through `OpenBackup` to add `blobs` rows (`import` = the Fog of World zip, `page_settings` = the page's `f2m_*` keys), saved by the native `createDocument` + `copyToUri`, and removed from the cache in `finally`. Restore copies the picked document into `cache/backup/` with `copyFromUri` (it returns the first 16 bytes: `SQLite format 3` means a plaintext backup, anything else page-aligned may be encrypted), opens it, asks for confirmation, then `createDatabaseReplacer` closes the live database, exports the backup into `crossfog.restoring.db` keyed with the device key (when the key is lost and `keyState` reads `lost`, with a new key generated in JS that `replaceLostDatabaseKey` keeps only after the swap and before the reopen, so a failed build leaves the old key and a failed reopen after it is kept leaves the new file live, since neither key opens the old one; a key that cannot be read in any other state ends the restore before the build), checks the counts, swaps files keeping `crossfog.replaced.db` until the new file has opened and migrated; `createDatabase` puts the old file back whenever a swap left no live one, and on the first open of a process keeps the replaced copy until the live file opens (putting it back if opening throws; a key-lost result leaves it beside the live file). A restore that cannot replace the saved fog still reloads the page (`fogNotReplaced`), and the controller refuses an import, a clear or a shared file while a restore runs. `createFlows` runs the whole restore under `HandOffFlow.hold`: no watch offer starts, an activity that commits meanwhile keeps its staged copy, and the hand-off runs again when the restore ends. `historyGate` (`src/db/gate.ts`) makes every store call shared and the swap exclusive. The page's settings travel as `needSettings` / `settings` and `applySettings` / `settingsApplied`; the restore waits for the ack before it reloads the page. `NotADatabaseError` cannot tell a wrong passphrase from a file that is no database, so the copy says both. `test/support/nodeSqliteDriver.ts` simulates keys per file path (node:sqlite cannot encrypt): the emulator is the real check, and `head -c 16` of the saved file is `SQLite format 3` only for an unencrypted backup. `createDocument` needs a person at the picker, so `SaveAsTest` covers the two copies on `file://` targets.

- Backup passphrase rules: the backup dialog (`src/ui/passphraseForm.ts`) rejects a passphrase under 8 characters and one of the form `x'<64 hex>'` or `x'<96 hex>'` (any case; SQLCipher takes it as the raw cipher secret, with no derivation step), both with plain copy; a restore accepts any non-empty text.

- Exports (`src/flows/exportFlow.ts`, `src/platform/{zipWriter,exportFiles,crashLog}.ts`, page: `fowExport.js`, `exportWarning.js`): the page writes the Fog of World tiles and sends them as `exportBinary` chunks (1 MiB raw at most, `exportId` is `[A-Za-z0-9-]` and `name` is `[a-z0-9]`, both because they become path segments; `files` is the count of files in the export, at most 65535, the no-ZIP64 limit). `createExportFlow` queues the chunks (WebView messages are not serialized, so "every file is complete" is seen once), keeps parts under `cache/export-<exportId>/parts/<name>/<index>`, joins a finished file into `Sync/<name>`, and when all `files` are in writes `Sync.zip` with `writeZip` (stored, fixed 1980 date so the zip's own headers say nothing about when it was made; the suggested file name still carries the day), saves it with `saveFileAs` (`createDocument` + `copyToUri`) and removes the directory in `finally`; a cancelled picker says nothing, a disagreement between chunks or any error drops the export with a message that carries no path. The next start removes any `export-*` directory and `cache/exports/` (`clearShareCopies`). `shareExport` (GPX, KML) deletes its cache copy as soon as `shareAsync` returns or fails. `scrubCoordinates` in `crashLog.ts` replaces every decimal number with three or more places by `[n]` and every `file://` or `/data`, `/storage`, `/sdcard`, `/mnt` path (which carries the export id) by `[path]`, in the message and not in the timestamp that has three decimals itself. Every cleanup (`clear`, the `finally` after a save, `clearShareCopies`, `shareExport`'s delete) logs only an error class and never turns a saved export into a failed one. The page's console lines print the reason or the error class only; `bench/export-warnings.test.js` scans `app/src/*.js` for a `console.*` call that names `why`, `explain`, `lat`, `lng`, `coords` or the like.

- Off-origin navigation: react-native-webview is deliberately unpatched and fails open when `decideNavigation` answers late, so the page must make no navigation but a link click. `test/adapter/links.test.ts` scans `app/index.html`, `app/src/` and `app/vendor/` for `<form>`, a `location` assignment, `<meta http-equiv=refresh>`, `formaction` and `.submit()`; a hit in vendored code is not patched but allowlisted in that test's `ALLOWED` with the reason it cannot leave the origin (none today).

- Native-to-page messages: every one goes through `createSend` (`src/bridge/send.ts`), never a bare `postMessage`. It posts and then schedules a no-op `setTimeout(0)`. Expo Modules v2 (expo-sqlite, expo-crypto; `ReactJSScheduler.post` in `expo-modules-v2-react`) settles promises with `runOnJSQueueThread` plus a microtask drain, outside React Native's RuntimeScheduler. A WebView command issued there waits in the scheduler's rendering updates until the end of the next task, so without the timer it reached the page only when the page next posted (#139). A microtask does not release it; only a new task does. A debug build can hide this, so check native-to-page changes on a Release build (`.maestro/history-release.yaml`).

## Tracked bundle

`generated/web.ts` is tracked. A `CROSSFOG_E2E=1` build or `pnpm generate` regenerates it, and the e2e flavour contains the developer-only "Dev: drop fog cache" button. After any e2e build run `git status --short` and restore it with `git checkout -- generated/web.ts`. Stage files by name, never with `git add -A`.

## Build and Maestro gotchas

- Gradle does not track `generated/web.ts` (it sits outside `mobile/`), so `createBundleReleaseJsAndAssets` can report `UP-TO-DATE` and ship the previous bundle. Before an Android build that changes the bundle (normal and e2e, either way, or an adapter change) run `rm -rf mobile/android/app/build/generated/{assets,res,sourcemaps}/react/release`, and check the build log shows the task ran. Hermes keeps some strings as UTF-16, so grep an APK bundle with `grep -a -c -P` on the spaced form.
- `android-mcp`'s device-side helper holds the UiAutomation connection, so Maestro fails with "Android driver did not start up in time". Kill the `com.wetest.uia2.Main` process on the device before a Maestro run; the next `Snapshot` restarts it.
- Maestro reports off-screen web view text as visible, so do not guard a swipe with `notVisible`. Use a fixed swipe, and assert that the app was left with `notVisible: "Expand or collapse panel"`.

## Tools

- Expo docs, EAS build status: the Expo MCP (`read_documentation`, `search_documentation`, `build_list`). Its builds run in the cloud and do not drive a local emulator.
- Android: `android-mcp` for the UI (never `adb shell uiautomator dump`, it crashes the service), and `adb`, the emulator and Gradle for builds, logs and root. There is no Android Studio MCP.
- Build and test output is large. Save it to a file and read `tail`/`jq` slices.

## Commit hook

A hook blocks `git commit` while comment-like lines are unreviewed (markdown, text and lockfiles are exempt). A new Maestro flow with no `#` lines still needed a review (probably because of the YAML `---` separator, which starts with `--`). Finish the edits, run the `pr-review-toolkit:comment-analyzer` agent alone with the first prompt line exactly `Repository: /Users/leo/Lab/defog`, wait for its report, re-run it if you changed a comment, then commit in a following turn. Do not bypass the hook.

## Private data

The owner's real backup (`Sync.zip`) is location history. Load it only on a device or through the page's own file input; never upload, commit or paste it.
